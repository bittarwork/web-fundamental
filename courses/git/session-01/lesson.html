هدف الجلسة

نفهم لماذا نحتاج Git، نفرّق بينه وبين GitHub، نثبّت الأداة ونضبط الاسم، ثم نحفظ أول لقطة بـ add وcommit.

01

الشرح النظري

ملاحظة: أمثلة الدورة تستخدم اسم Osama Bittar كمرجع موحّد لجميع الطلاب.

1) ما هو Version Control؟

نظام التحكم بالإصدارات يحفظ تاريخ الملفات: ماذا تغيّر، متى، ومن الذي حفظ اللقطة. بدل مجلدات مثل site-final و site-final-2 يكون لديك سجل واحد يمكن الرجوع إليه.

تشبيه: Git ألبوم صور للمشروع. كل commit صورة واضحة للكود في لحظة معينة، مع تعليق يشرح لماذا التُقطت.

2) الفرق بين Git و GitHub

Git

برنامج على جهازك. يعمل بلا إنترنت بعد التثبيت. يحفظ المستودع في مجلد .git.

GitHub

موقع على الشبكة يستضيف نسخاً من المستودعات، ويعطي قضايا وطلبات دمج وصفحات نشر. نصل إليه من الجلسة 03.

يمكن استخدام Git وحدك على الجهاز. GitHub اختياري للتخزين السحابي والتعاون، وهو الأشهر في سوق العمل بجانب خدمات مشابهة.

3) تثبيت Git وإعداد الاسم والبريد

بعد التثبيت افحص الإصدار، ثم عرّف من أنت. كل commit يحمل هذا الاسم.

git --version

git config --global user.name "Osama Bittar"
git config --global user.email "osama.bittar@example.com"
git config --global init.defaultBranch main
git config --list
--global يعني لكل المستودعات على هذا الجهاز. غيّر البريد لاحقاً إلى بريد حساب GitHub الحقيقي عند الربط في الجلسة 03.

4) مناطق العمل الثلاث

  • Working tree: الملفات كما تراها في المجلد.
  • Staging (Index): ما اخترته للصورة التالية عبر git add.
  • Repository: التاريخ المحفوظ بعد git commit.

لا تُحفظ اللقطة حتى تمرّ بالمرحلتين: اختيار ثم تثبيت.

5) git init و git status

git init ينشئ مستودعاً جديداً داخل المجلد الحالي. git status يخبرك: ما تغيّر، وما في الانتظار، وعلى أي فرع أنت.

لا تنفّذ init داخل مجلد أب فيه Git مسبقاً إلا إذا كنت تقصد مستودعاً متداخلاً — للمبتدئ: مجلد مشروع واحد = مستودع واحد.

6) git add و git commit

git add file يضع ملفاً في الانتظار. git add . يضيف كل التغييرات في المجلد الحالي. ثم git commit -m "message" يثبّت اللقطة.

رسالة الـ commit جملة قصيرة بالإنجليزية توضّح السبب لا قائمة الملفات.

7) git log

يعرض التاريخ من الأحدث إلى الأقدم: المعرّف، المؤلف، التاريخ، الرسالة. git log --oneline عرض مختصر سطر لكل لقطة.

أمثلة عملية

مثال 1: إنشاء مجلد المشروع

mkdir academy-notes
cd academy-notes
git init
git status

يفترض أن ترى فرعاً اسمه main ولا commits بعد.

مثال 2: أول ملف وأول لقطة

echo "Trainer: Osama Bittar" > notes.txt
git add notes.txt
git status
git commit -m "Add trainer notes file"
git log --oneline

مثال 3: تعديل ثم لقطة ثانية

echo "Course: Git and GitHub" >> notes.txt
git add notes.txt
git commit -m "Document the Git course title"
git log --oneline

مثال 4: إضافة ملفين دفعة واحدة

echo "<h1>Osama Bittar</h1>" > index.html
echo "body { font-family: sans-serif; }" > style.css
git add index.html style.css
git commit -m "Add starter HTML and CSS"

تمارين عملية

2 مستودع notes

mkdir hello-git
cd hello-git
git init

git add hello.txt

ملخص الجلسة

  • Git يحفظ تاريخ المشروع على الجهاز
  • GitHub خدمة شبكة للعرض والتعاون — ليست Git نفسه
  • ثلاث مناطق: العمل، الانتظار، المستودع
  • الدورة اليومية: status ثم add ثم commit ثم log

واجب الجلسة

  • ثبّت Git واضبط الاسم والبريد وفرع main الافتراضي
  • أنشئ مستودع academy-notes بثلاث لقطات على الأقل
  • أضف ملفاً يذكر المدرب Osama Bittar واحفظه في commit مستقل
