ننشئ حساباً ومستودعاً على GitHub، نربط origin، ندفع العمل، ونستنسخ مشروعاً موجوداً مع فهم الواجهة الأساسية.

03

الشرح النظري

1) حساب GitHub والملف الشخصي

GitHub منصة لاستضافة مستودعات Git. الحساب المجاني يكفي لهذه الدورة. اختر اسم مستخدم واضحاً (بالإنجليزية)، وأضف صورة واسماً ظاهراً مثل Osama Bittar، وسيرة قصيرة في الملف الشخصي.

من الصفحة الرئيسية تصل إلى: مستودعاتك، الإشعارات، الإعدادات، واستكشاف مشاريع الآخرين.

2) مستودع عام وخاص

Public

أي شخص يرى الكود. مناسب لمعرض أعمال الدورة وصفحات التخرج.

Private

تراه أنت ومن تدعوه. مناسب لتجارب فيها بيانات غير جاهزة للعرض.

المستودع (Repository) = مشروع Git على GitHub مع صفحة ويب، قضايا، وإعدادات.

3) إنشاء Repository من الموقع

New repository ثم:

  • الاسم: academy-notes (بدون فراغات).
  • الوصف جملة واحدة بالإنجليزية.
  • لا تُضف README من الموقع إذا كان لديك مستودع محلي جاهز — تجنّب تاريخين مختلفين في البداية.
  • يمكنك لاحقاً إضافة رخصة (مثل MIT) من الواجهة أو بملف.
README: ملف يُعرض أعلى صفحة المستودع. نكتبه في المشروع ونرفعه. لا تخلطه مع ملفات الدورة في منصة الدروس.

4) git remote و git push

remote لقب لعنوان على الشبكة. الاسم الشائع origin يعني «نسخة GitHub». 

git remote add origin https://github.com/USERNAME/academy-notes.git
git remote -v
git branch -M main
git push -u origin main

-u يربط الفرع المحلي بتتبع الفرع البعيد، فلاحقاً يكفي غالباً git push و git pull.

استبدل USERNAME باسم حسابك. في أمثلة الصف نتخيّل osama-bittar.

5) HTTPS ومفاتيح الوصول

GitHub لم يعد يقبل كلمة مرور الحساب مع HTTPS. عند الدفع يطلب Personal Access Token (من Settings → Developer settings) أو نستخدم SSH في الجلسة 05.

احفظ الـ Token ككلمة مرور في مربع Git، ولا تلصقه داخل ملف المشروع.

6) git clone و git pull و git fetch

  • clone: نسخ مستودع كامل من GitHub إلى مجلد جديد (أول مرة).
  • fetch: يجلب التحديثات دون دمجها في ملفاتك.
  • pull: fetch ثم دمج في الفرع الحالي — لتحديث نسختك.
git clone https://github.com/USERNAME/academy-notes.git
cd academy-notes
git pull
clone ≠ download ZIP. الـ ZIP نسخة بلا ارتباط Git كامل. للعمل اليومي استخدم clone.

7) واجهة GitHub: Code و Commits

  • Code: الملفات، الفرع الحالي، زر Clone، زر Add file.
  • Commits: تاريخ اللقطات مع الرسائل والمؤلف Osama Bittar إن كان هذا إعداد Git.
  • Branches: قائمة الفروع على السيرفر.
  • Insights / Settings: إحصاءات وإعدادات (الخصوصية، الصفحات لاحقاً، التعاون).

يمكنك تعديل ملف من المتصفح وعمل commit هناك. في الدورة فضّل التعديل محلياً ثم push حتى تبقى العادة الاحترافية.

أمثلة عملية

مثال 1: ربط مشروع موجود

cd academy-notes
git remote add origin https://github.com/osama-bittar/academy-notes.git
git push -u origin main

بعد النجاح حدّث صفحة GitHub: تظهر الملفات والـ commits.

مثال 2: التحقق من العنوان البعيد

git remote -v
git status

status يذكر أن فرعك يتتبع origin/main إن نجح الربط.

مثال 3: تعديل ثم دفع

echo "Published by Osama Bittar" >> notes.txt
git add notes.txt
git commit -m "Note the publisher name"
git push

مثال 4: استنساخ على مجلد آخر (محاكاة جهاز جديد)

cd ..
git clone https://github.com/osama-bittar/academy-notes.git academy-notes-copy
cd academy-notes-copy
git log --oneline

تمارين عملية

1 إنشاء المستودع

أنشئ مستودعاً عاماً فارغاً على GitHub باسم academy-notes دون README إن كان لديك مشروع محلي.

GitHub → New → الاسم academy-notes → Public → Create repository بدون تهيئة ملفات إن المشروع موجود محلياً.

2 الدفع الأول

اربط origin وادفع main.

git remote add origin https://github.com/USERNAME/academy-notes.git
git push -u origin main

3 سحب التحديث

اشرح متى تستخدم pull بعد أن يعدّل زميلك على GitHub.

قبل أن تبدأ يوم العمل، ومن بعد كل دمج على GitHub: git pull حتى لا تعمل على نسخة قديمة.

📌

ملخص الجلسة

  • GitHub يستضيف المستودع ويعرض الملفات والسجل
  • remote origin + push يرفع عملك
  • clone للنسخة الأولى · pull للتحديث لاحقاً
  • HTTPS يحتاج Token لا كلمة مرور الحساب
