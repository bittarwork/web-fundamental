هدف الجلسة

نحل تعارض دمج بسيط، ننشر صفحة عبر GitHub Pages، نتعرّف على SSH والوسوم والإصدارات، ونسلّم مستودعاً نظيفاً.

05

الشرح النظري

1) تعارضات الدمج

يحدث التعارض عندما يغيّر فرعان نفس الأسطر بطريقتين مختلفتين. Git يتوقف ويضع علامات في الملف: 

<<<<<<< HEAD
Price: 29 €
=======
Price: 39 €
>>>>>>> feature/price

خطوات الحل:

  1. افتح الملف واختر النص النهائي (أو ادمج المعنيين يدوياً).
  2. احذف علامات التعارض بالكامل.
  3. git add للملف.
  4. أكمل الدمج بـ git commit (غالباً يفتح رسالة دمج جاهزة).
للوقاية: pull كثيراً، وفروع قصيرة العمر، وتجنب أن يعدّل شخصان نفس الفقرة بلا تنسيق.

2) GitHub Pages

خدمة تنشر ملفات HTML/CSS/JS من المستودع كموقع عام. لمستودع username.github.io يكون العنوان على جذر الحساب، ولمستودع عادي غالباً: https://username.github.io/repo-name/.

من Settings → Pages اختر الفرع (غالباً main) والمجلد / أو /docs. الملف الافتراضي index.html.

مثال حي: مرجع هذه الأكاديمية منشور بأسلوب GitHub Pages — الفكرة نفسها: ملفات ثابتة من مستودع عام.

3) SSH مقابل HTTPS

HTTPS

سهل البداية. يحتاج Token عند الدفع. مناسب إن لم تضبط المفاتيح بعد.

SSH

زوج مفاتيح على الجهاز. تضيف المفتاح العام في GitHub → SSH keys ثم تستخدم git@github.com:USER/REPO.git.

ssh-keygen -t ed25519 -C "osama.bittar@example.com"
# press Enter to accept the default file
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub

انسخ المفتاح العام فقط (ملف .pub) إلى GitHub. لا تشارك الملف الخاص.

ssh -T git@github.com
git remote set-url origin git@github.com:USERNAME/academy-notes.git

4) Tags و Releases

الوسم علامة على commit معيّن، مثل إصدار v1.0.0. Release على GitHub صفحة عامة لذلك الوسم مع ملاحظات التحميل. 

git tag -a v1.0.0 -m "First public academy notes"
git push origin v1.0.0

ثم GitHub → Releases → Draft a new release واختر الوسم واكتب الملاحظات بالإنجليزية.

5) رسائل الـ commit الجيدة

  • أمر قصير في المضارع: Add contact page لا «fixed stuff».
  • لقطة واحدة لفكرة واحدة قدر الإمكان.
  • لا تحفظ ملفات لا علاقة لها بالتغيير.

6) حماية فرع main

من Settings → Branches يمكن منع الدفع المباشر إلى main وإلزام Pull Request. حتى بدون تفعيل القواعد: اتفاق الفريق يكفي في الدورة — لا git push --force على main.

force push يعيد كتابة التاريخ البعيد وقد يمسح عمل الزملاء. خارج هذه الدورة لا تستخدمه إلا بفهم كامل وعلى فرعك الخاص.

7) مشروع ختامي

مستودع واحد جاهز للتسليم:

  • صفحة index.html باسم Osama Bittar.
  • ملف تجاهل مناسب وبدون أسرار.
  • تاريخ commits واضح على main بعد دمج PR واحد على الأقل.
  • GitHub Pages يعمل ويظهر الموقع.
  • وسم v1.0.0 اختياري ومستحسن.

GitHub Actions (التشغيل التلقائي عند الدفع) موضوع لاحق؛ يكفي أن تعرف أنه موجود في تبويب Actions. GitHub Desktop واجهة رسومية اختيارية — الأوامر في هذه الدورة هي الأساس.

أمثلة عملية

مثال 1: صفحة جاهزة للنشر

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Osama Bittar — Academy</title>
  </head>
  <body>
    <h1>Osama Bittar</h1>
    <p>Git and GitHub course notes.</p>
    <p>Sample price: 29 €</p>
  </body>
</html>

مثال 2: تفعيل Pages بعد الدفع

Settings → Pages → Branch: main → folder: / (root) → Save. انتظر دقيقة ثم افتح الرابط.

مثال 3: حل تعارض مبسّط

git switch main
git merge feature/price
# if conflict: edit the file, remove markers
git add index.html
git commit -m "Merge price update for academy page"

تمارين عملية

1 نشر الصفحة

ادفع index.html إلى main وفعّل Pages. افتح الرابط العام.

Settings → Pages → Source: Deploy from a branch → main → / → Save. الرابط يظهر في نفس الصفحة.

2 وسم الإصدار

أنشئ الوسم v1.0.0 وادفعه.

git tag -a v1.0.0 -m "First public academy notes"
git push origin v1.0.0

3 قائمة تسليم

تحقق: لا .env في الملفات، main محدّث، Pages يعمل، اسم المدرب ظاهر في الصفحة.

git status
git log --oneline
# confirm .gitignore includes .env
# open the Pages URL in the browser
