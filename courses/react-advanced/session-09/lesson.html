هدف الجلسة

نلغي الطلب عند مغادرة الصفحة ونتجاهل الرد القديم حتى لا تُعرض تفاصيل كورس خاطئ.

09

الشرح النظري

1) سباق الطلبات

المستخدم يفتح كورس 1 ثم بسرعة 2. إن وصل رد 1 متأخراً قد يستبدل بيانات 2.

2) AbortController

مرّر signal إلى fetch. في cleanup للأثر استدع abort().

3) الإغلاق القديم (stale closure)

أثر يعتمد على id لكن الدالة الداخلية ترى قيمة قديمة إن نقص الاعتماد. ضع courseId في المصفوفة.

4) تجاهل الرد

حتى بلا abort: متغير let cancelled = false في الأثر، وفي النهاية cancelled = true.

لا تترك fetch بلا cleanup في صفحات التفاصيل الديناميكية.
💻

أمثلة عملية

مثال 1: إلغاء

useEffect(() => {
  const controller = new AbortController();
  async function load() {
    try {
      const response = await fetch(url, { signal: controller.signal });
      if (!response.ok) throw new Error("Failed");
      setCourse(await response.json());
    } catch (error) {
      if (error.name === "AbortError") return;
      setError(error.message);
    }
  }
  load();
  return () => controller.abort();
}, [courseId]);

مثال 2: عنوان يعتمد على المعرّف

const url = "https://jsonplaceholder.typicode.com/posts/" + courseId;

مثال 3: علَم الإلغاء

let cancelled = false;
// after await: if (cancelled) return;
return () => { cancelled = true; };

ملخص الجلسة

  • الرد المتأخر قد يكون للكورس السابق
  • abort في cleanup
  • الاعتماد الكامل يمنع الإغلاق القديم
