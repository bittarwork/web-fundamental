الشرح النظري

1) Nested layouts

تخطيط لوحة فيه قائمة جانبية وOutlet للمحتوى. المسارات الأبناء تُرسم داخله.

2) Outlet context

مرّر بيانات التخطيط للأبناء بلا نفخ props في كل Route.

3) useSearchParams

الفلاتر في الرابط قابلة للمشاركة: ?q=react&min=29

4) Protected routes

إن لم توجد جلسة، Navigate إلى /login مع state من أين جاء المستخدم.

هذا ليس أمناً حقيقياً للسيرفر. حماية الواجهة تمنع التجول العرضي فقط.
💻

أمثلة عملية

مثال 1: تخطيط محمي

function RequireSession({ children }) {
  const { session } = useSession();
  const location = useLocation();
  if (!session) {
    return <Navigate to="/login" replace state={{ from: location }} />;
  }
  return children;
}

مثال 2: فلاتر في URL

const [params, setParams] = useSearchParams();
const query = params.get("q") || "";

function onSearch(value) {
  setParams({ q: value });
}

مثال 3: سياق الـ Outlet

function DeskLayout() {
  return (
    <div>
      <aside>Osama Bittar</aside>
      <Outlet context={{ currency: "€" }} />
    </div>
  );
}

تمارين عملية

1 حارس

غلّف /desk بـ RequireSession.

انظر مثال 1 وضع المسارات الأبناء تحته.

2 بحث

حقل يحدّث ?q= ويعيد التصفية.

setParams(query ? { q: query } : {});

const { currency } = useOutletContext();

ملخص الجلسة

  • التخطيط المتداخل يثبت الصدفة
  • الرابط مصدر حقيقة للفلاتر
  • حماية الواجهة ≠ أمن API

  • ابنِ login وهمي يضع session في context
  • لوحة /desk/courses مع بحث في URL
