هدف الجلسة

نكتب اختبارات Vitest تحاكي المستخدم: يرى النص، ينقر، ويظهر الخطأ — لا تفاصيل الـ state الداخلية.

13

الشرح النظري

1) Testing Library

ابحث كما يبحث المستخدم: getByRole, getByLabelText. تجنّب test-id إلا للضرورة.

2) Vitest + jsdom

Vite يدعم vitest. render من @testing-library/react ثم userEvent.

3) غير متزامن

findBy ينتظر ظهور العنصر بعد fetch. استخدم waitFor عند الحاجة.

4) ماذا نختبر؟

السلوك الظاهر: رسالة خطأ، تعطيل زر، ظهور السعر €. لا تختبر أن useState استُدعي.

اختبار واحد جيد أفضل من عشرة هشة ترتبط بأسماء class.
💻

أمثلة عملية

مثال 1: عداد

import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";

test("increments seats", async () => {
  const user = userEvent.setup();
  render(<SeatCounter />);
  await user.click(screen.getByRole("button", { name: "+" }));
  expect(screen.getByText("Seats: 1")).toBeInTheDocument();
});

مثال 2: خطأ نموذج

await user.click(screen.getByRole("button", { name: "Save" }));
expect(screen.getByText(/name is required/i)).toBeInTheDocument();

مثال 3: السعر

render(<Price amount={49} />);
expect(screen.getByText("49 €")).toBeInTheDocument();
