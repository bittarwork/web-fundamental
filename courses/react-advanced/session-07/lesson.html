هدف الجلسة

نعزل خطأ رسم في فرع من الشجرة حتى لا تسقط الأكاديمية كلها، ونوفّر إعادة محاولة.

07

الشرح النظري

1) لماذا Error Boundary؟

خطأ غير ملتقط أثناء الرسم يفرّغ الشاشة. الحد يمسك الخطأ في الأبناء ويعرض بديلاً.

2) قيد React

حتى الآن الحدود تُكتب كـ class: getDerivedStateFromError و componentDidCatch. الـ hooks لا تستبدلها هنا.

3) ماذا تمسك؟

أخطاء الرسم ودورة الحياة في الأبناء. لا تمسك أخطاء معالجات الأحداث أو الوعود — تلك بـ try/catch.

4) استعادة

زر Retry يصفّر hasError. غيّر key للحد لإعادة تركيب الشجرة.

💻

أمثلة عملية

مثال 1: حد بسيط

class SectionBoundary extends Component {
  state = { hasError: false };
  static getDerivedStateFromError() {
    return { hasError: true };
  }
  componentDidCatch(error) {
    console.error("Section failed", error);
  }
  render() {
    if (this.state.hasError) {
      return (
        <div>
          <p>This block failed.</p>
          <button onClick={() => this.setState({ hasError: false })}>Retry</button>
        </div>
      );
    }
    return this.props.children;
  }
}

مثال 2: عزل التفاصيل

<SectionBoundary>
  <CourseDetails />
</SectionBoundary>

مثال 3: مكوّن يتعمد العطل للتدريب

function Boom({ crash }) {
  if (crash) throw new Error("Demo crash for Osama");
  return <p>Details ok</p>;
}

ملخص الجلسة

  • اعزل الفروع الهشة
  • الأحداث غير المتزامنة تحتاج try/catch
  • Retry يصفّر الحالة أو يغيّر key

  • أضف حداً حول Outlet اللوحة
  • زر يفعّل Boom للتدريب ثم Retry
  • لا تبتلع الأخطاء بصمت بلا سجل
