هدف الجلسة

نبني خطافاً صغيراً يخزّن النتائج حسب مفتاح حتى لا نعيد طلب القائمة في كل زيارة خلال الجلسة.

10

الشرح النظري

1) لماذا cache؟

التنقّل قائمة → تفاصيل → قائمة يعيد fetch بلا داعٍ. ذاكرة Map بالمفتاح توفر اللقطة الأخيرة.

2) مفاتيح الاستعلام

["courses"] أو ["course", id]. أي تغيّر في المفتاح = خانة مختلفة.

3) الإبطال invalidate

بعد حفظ نموذج احذف المفتاح أو أعد الجلب حتى لا تبقى قائمة قديمة.

4) خطاف مشترك

هذا تبسيط تعليمي لفكرة مكتبات مثل TanStack Query — نفهم الفكرة قبل إضافة مكتبة.

الذاكرة هنا في RAM التبويب. تحديث الصفحة يفرّغها إلا إذا خزّنت لاحقاً.

أمثلة عملية

مثال 1: مخزن بسيط

const memory = new Map();

export function readCache(key) {
  return memory.get(key);
}

export function writeCache(key, value) {
  memory.set(key, value);
}

export function invalidate(key) {
  memory.delete(key);
}

مثال 2: useCachedCourses

export function useCachedCourses() {
  const key = "courses";
  const cached = readCache(key);
  const [data, setData] = useState(cached || []);
  const [loading, setLoading] = useState(!cached);

  useEffect(() => {
    if (cached) return;
    let cancelled = false;
    getCourses().then((rows) => {
      if (cancelled) return;
      writeCache(key, rows);
      setData(rows);
      setLoading(false);
    });
    return () => { cancelled = true; };
  }, [cached]);

  return { data, loading };
}

مثال 3: بعد الحفظ

invalidate("courses");

تمارين عملية

1 مفتاح سعر

خزّن قائمة فيها price باليورو.

writeCache("courses", rows.map((row) => ({ ...row, price: 39 })));

2 تخطي الجلب

إن وُجدت الذاكرة لا تعرض Loading كاملاً.

loading الابتدائي !cached كما في المثال.

3 إبطال

بعد نموذج تواصل ادعُ invalidate.

invalidate("courses");
