هدف الجلسة

نجعل اللوحات والنماذج قابلة للاستخدام بالكيبورد وللقارئات، مع تركيز صحيح في الحوارات.

08

الشرح النظري

1) لوحة المفاتيح أولاً

كل تفاعل مهم يصل إليه Tab. لا تعتمد على hover وحده. الأزرار الحقيقية لا div مع onClick فقط إلا مع دور ولوحة مفاتيح.

2) إدارة التركيز

عند فتح Modal انقل التركيز إلى داخله، وعند الإغلاق أعده للزر الذي فتحه. هذا نمط Dialog.

3) ARIA بحذر

العنصر الأصلي أفضل: button, nav, main. استخدم aria-expanded وaria-selected عندما يحاكي المكوّن ودجة أصلية.

4) النماذج

كل حقل له label. رسالة الخطأ ترتبط بـ aria-describedby وaria-invalid.

الترتيب المرئي = ترتيب DOM قدر الإمكان حتى لا يقفز Tab عشوائياً.
💻

أمثلة عملية

مثال 1: خطأ مرتبط

const errorId = useId();
<input aria-invalid={Boolean(error)} aria-describedby={error ? errorId : undefined} />
{error && <p id={errorId}>{error}</p>}

مثال 2: زر قائمة

<button type="button" aria-expanded={open} aria-controls="desk-menu" onClick={toggle}>
  Menu
</button>

مثال 3: حوار

<div role="dialog" aria-modal="true" aria-labelledby="dialog-title">
  <h2 id="dialog-title">Confirm booking — 29 €</h2>
</div>

تمارين عملية

1 تسمية

حقل بريد مع label ظاهر واسم Osama كقيمة افتراضية اختيارية.

<label htmlFor={id}>Email</label>
<input id={id} type="email" />

2 قائمة Accordion

aria-expanded على الرأس.

true عندما يكون اللوح مفتوحاً.

3 Escape

أغلق الحوار بمفتاح Escape.

useEffect(() => {
  function onKey(event) {
    if (event.key === "Escape") onClose();
  }
  window.addEventListener("keydown", onKey);
  return () => window.removeEventListener("keydown", onKey);
}, [onClose]);
