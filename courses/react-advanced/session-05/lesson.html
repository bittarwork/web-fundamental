هدف الجلسة

نحمّل صفحات ثقيلة عند الحاجة مع واجهة انتظار واضحة عبر lazy وSuspense.

05

الشرح النظري

1) لماذا التقسيم؟

حزمة واحدة ضخمة تبطئ أول رسم. قسّم صفحات لوحة التحكم عن صفحة الحجز.

2) React.lazy

يستورد المكوّن كـ Promise عند أول رسم. يحتاج default export.

3) Suspense

يغلف الحدود ويعرض fallback إلى أن يجهز الكود. يمكن تداخل الحدود.

4) تقسيم المسارات

كل Route ثقيل = ملف صفحة lazy. التخطيط الخفيف يبقى في الحزمة الأولى.

Fallback: هيكل بطاقات رمادي أهدأ من كلمة Loading وحدها.
💻

أمثلة عملية

مثال 1: صفحة كسولة

const DashboardPage = lazy(() => import("./pages/DashboardPage"));

<Suspense fallback={<p>Loading academy desk...</p>}>
  <DashboardPage />
</Suspense>

مثال 2: مع Router

<Route path="dashboard" element={
  <Suspense fallback={<Skeleton />}>
    <DashboardPage />
  </Suspense>
} />

مثال 3: تصدير افتراضي

export default function DashboardPage() {
  return <h1>Desk of Osama Bittar</h1>;
}

تمارين عملية

2 هيكل انتظار

fallback مكوّن Skeleton بثلاث بطاقات.

ثلاث div بخلفية رمادية أفضل من نص فقط.

3 حدّان

Suspense حول لوحة وآخر حول إعدادات.

خطأ في أحدهما لا يجب أن يمنع ظهور الآخر إن فصلت الحدود لاحقاً مع Error Boundary.
