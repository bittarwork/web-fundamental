هدف الجلسة

نعتمد نسخ Hostinger، تحديثات أمنية، نشراً من Git، وعادات يمكن أخذها إلى وظيفة حقيقية.

الشرح النظري

1) النسخ في hPanel

  • Snapshots: لقطة سريعة قبل تجربة خطرة (تحديث كبير، تغيير OS).
  • Backups: النسخ الأسبوعية حسب الخطة. اعرف كيف تستعيد من اللوحة قبل أن تحتاجها.

2) تحديثات أمنية

apt update && apt upgrade -y
docker compose pull
docker compose up -d

جدولة أسبوعية أفضل من نسيان شهر. لا ترقِّ إصدار Ubuntu الرئيسي دون لقطة.

3) النشر من Git (مسار عمل)

cd /root/academy
git pull
docker compose up -d --build

في الفرق: فرع main محمي، والسيرفر يسحب إصداراً مختبراً فقط. لا تطوّر على السيرفر مباشرة.

4) مراقبة خفيفة

df -h
free -h
docker compose ps
journalctl -u nginx -n 20 --no-pager

5) الانتقال للعمل

  • نفس الأفكار: SSH بمفاتيح، مستخدم غير root، جدار، Docker، بروكسي، شهادات، نسخ.
  • الفارق: بيئات staging/production، أسرار في مدير أسرار لا في Git، وأحياناً أنابيب CI تدفع إلى السيرفر.
  • التذاكر: لا تعطِ صلاحية root في دردشة. وثّق IP والنطاق في مكان الفريق الآمن.
  • Hostinger يبقى خياراً عملياً للمشاريع الصغيرة والمتوسطة باليورو؛ الشركات قد تستخدم بنية أكبر لكن أوامرك نفسها تنقل.

6) قائمة تسليم الدورة

  • VPS Ubuntu Running على Hostinger
  • نطاق من Hostinger + HTTPS
  • تطبيق Docker compose
  • صفحة تظهر Osama Bittar وسعر عيّنة €
  • لقطة Snapshot قبل التسليم

2 سحب

git pull ثم compose up --build.

ملخص الجلسة

  • Snapshot عادة لا بطولة
  • Git مصدر الحقيقة لا تعديل الإنتاج باليد
  • نفس المهارات تُنقل للعمل مع صرامة أكبر

واجب الجلسة

  • تسليم: رابط HTTPS + ملخص الخطة باليورو + تأكيد أن المزوّد Hostinger
  • لا ترفق كلمات مرور
  • راجع الجدار والمفتاح
