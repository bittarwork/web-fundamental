هدف الجلسة

نضع Nginx على المنفذ 80/443 أمام حاوية Docker، ونفعّل HTTPS بعد ربط نطاق Hostinger.

11

الشرح النظري

1) Reverse proxy

الزائر يصل إلى النطاق على 443. Nginx يمرّر الطلب إلى الحاوية على 127.0.0.1:8080. الحاوية لا تُفتح على الإنترنت مباشرة.

2) موقع Nginx

# /etc/nginx/sites-available/academy
server {
  listen 80;
  server_name example.com www.example.com;

  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
  }
}
ln -s /etc/nginx/sites-available/academy /etc/nginx/sites-enabled/
nginx -t
systemctl reload nginx

استبدل example.com بنطاقك من Hostinger. أزل الموقع الافتراضي إن تعارض.

3) شهادة Let's Encrypt

apt install -y certbot python3-certbot-nginx
certbot --nginx -d example.com -d www.example.com

البريد لرسائل التجديد. وافق على الشروط. Certbot يضبط 443 وإعادة التوجيه من 80.

DNS يجب أن يشير للنطاق قبل الشهادة. وإلا يفشل التحقق.

4) جدار ناري

80 و443 مفتوحان من الجلسة 07. الحاوية تبقى على localhost:8080.

5) Hostinger

لا حاجة لنقل النطاق خارج Hostinger. أبقِ DNS هناك. إن وفّر Hostinger SSL في اللوحة للمواقع المشتركة فذلك مسار مختلف؛ على VPS نستخدم certbot كما فوق.
