هدف الجلسة

نفهم أين يعيش الموقع على الإنترنت، ولماذا ننتقل إلى VPS، ولماذا نلتزم بـ Hostinger فقط في هذه الدورة.

01

الشرح النظري

نطاق الدورة: المزوّد الوحيد هو Hostinger (hPanel وVPS وDomains). لا نخلط مع مزوّدين آخرين حتى يبقى كل زر في مكانه.

1) أين يعيش الموقع؟

جهاز الزائر يطلب عنواناً. خادم يجيب بملفات HTML/CSS/JS أو تطبيق Node/React مُبنى. هذا الخادم مستأجر عند شركة استضافة.

تشبيه: GitHub Pages = رفّ في مكتبة عامة. الاستضافة المشتركة = شقة في مبنى يديره الحارس. VPS = شقة بمفتاحك أنت (root).

2) أنواع الاستضافة

Shared

سهل ورخيص. موارد مشتركة. مناسب لموقع تعريفي صغير بلا Docker.

VPS (KVM)

جهاز افتراضي معزول، صلاحية root، تختار Ubuntu وتثبت ما تشاء. هذا مسار الدورة.

GitHub Pages ممتاز للدروس الثابتة. عندما تحتاج قاعدة بيانات أو Docker أو خلفية API، تنتقل إلى VPS.

3) لماذا Hostinger هنا؟

  • لوحة hPanel واضحة: VPS، Domains، الفواتير بالعملات المتاحة ومنها اليورو.
  • خطط KVM 1 / 2 / 4 / 8 بمعالجات وذاكرة وNVMe.
  • قالب Ubuntu، Browser Terminal، مفاتيح SSH، جدار ناري، لقطات ونسخ أسبوعية.
  • شراء النطاق وإدارة DNS من نفس الحساب.

4) hPanel باختصار

بعد تسجيل الدخول: Domains للنطاقات، VPS للسيرفرات، Billing للدفع. صفحة Overview للسيرفر تعرض IP والحالة وBrowser Terminal.

الأسعار باليورو. غيّر عملة العرض إن لزم، وتحقق من سعر التجديد لا سعر الشهر الأول فقط.

أمثلة عملية

مثال 1: متى تترك Pages؟

صفحة Portfolio ثابتة تبقى على Pages. تطبيق React يحتاج API أو Docker → VPS على Hostinger.

مثال 2: إنشاء حساب

hostinger.com → إنشاء حساب بالبريد → أكّد البريد → ادخل hPanel. استخدم اسماً واضحاً مثل Osama Bittar في بيانات الفاتورة.

مثال 3: أين VPS؟

القائمة العلوية → VPS. إن لم تشترِ بعد سترى خطط KVM. بعد الشراء تظهر بطاقة السيرفر وحالته.
