الشرح النظري

1) لماذا Compose؟

بدل أوامر run طويلة: ملف يصف الخدمات. أمر واحد يشغّل الموقع. في العمل هذا الملف هو عقد الفريق.

2) compose.yaml

services:
  web:
    build: .
    ports:
      - "8080:80"
    restart: unless-stopped
cd /root/academy
docker compose up -d
docker compose ps
docker compose logs -f
docker compose down

3) متغيرات البيئة

ملف .env بجانب compose للقيم غير السرية للعرض. الأسرار الحقيقية لا تُرفع إلى GitHub.

4) إعادة البناء بعد تعديل HTML

docker compose up -d --build

5) تعارض المنفذ 80

إن كان Nginx النظام ماسكاً 80: أوقفه أثناء تجربة الحاوية على 80، أو اترك الحاوية على 8080 حتى جلسة البروكسي.

systemctl stop nginx

ملخص الجلسة

  • ملف واحد يصف التشغيل
  • build بعد تغيّر الملفات المنسوخة في الصورة
  • restart يحمي بعد الإقلاع

واجب الجلسة

  • تطبيق الأكاديمية يعمل بـ compose
  • وثّق الأمرين up وdown
  • لا ترفع .env فيه كلمات سر
