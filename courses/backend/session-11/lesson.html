هدف الجلسة

نتحقق من المدخلات في الطلب والنموذج، ونبني معالجاً مركزياً للأخطاء غير المتزامنة وقاعدة البيانات و404.

11

الشرح النظري

1) Request Validation و Schema Validation

تحقق الجسم قبل قاعدة البيانات (طول الاسم، بريد، السعر ≥ 0). الـ Schema طبقة ثانية.

2) Centralized Error Handler

وسيط بأربعة معاملات (err, req, res, next). أرسل message آمن للعميل. التفاصيل في السجل للخادم فقط.

3) Async Errors

غلّف المتحكم: catchAsync(fn) يستدعي Promise.resolve(fn(...)).catch(next).

4) Database Errors و Invalid IDs و Not Found

CastError لـ ObjectId غير صالح → 400. document null → 404. مسار غير موجود → 404 أخير.

5) API Error Responses

{ "success": false, "message": "Title is required" }
💻

أمثلة عملية

مثال 1: غلاف async

export const asyncHandler = (fn) => (req, res, next) => {
  Promise.resolve(fn(req, res, next)).catch(next);
};

مثال 2: معالج

export function errorHandler(err, req, res, next) {
  const status = err.statusCode || 500;
  res.status(status).json({ success: false, message: err.message || "Server error" });
}

مثال 3: 404

app.use((req, res) => {
  res.status(404).json({ success: false, message: "Route not found" });
});
