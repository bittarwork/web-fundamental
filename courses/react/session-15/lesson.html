هدف الجلسة

نحلّل مشروعاً حقيقياً (كتالوج أكاديمية)، نصمم Architecture، نقسم التطبيق إلى Components وصفحات، ونبدأ التنفيذ الفعلي بكل مفاهيم الدورة حتى Context عند الحاجة.

15

الشرح النظري — تحليل المشروع

1) فكرة المنتج

Academy Catalog — واجهة تعرض كورسات المنصة. المدرب في الأمثلة: Osama Bittar. الأسعار باليورو (€). الطالب يتصفّح القائمة، يبحث، يفتح التفاصيل، ويرسل نموذج اهتمام.

تشبيه: واجهة المتجر لكن للمنتجات التعليمية: رف (قائمة) · بطاقة سعر · صفحة منتج · نموذج تواصل.

2) ماذا يجب أن يغطي المشروع؟

  • Components و Props و State
  • useState و useEffect
  • Routing و Dynamic Routes
  • APIs و Forms
  • Context API عند الحاجة (المدرب والعملة في الهيدر)
  • تنظيم المجلدات من الجلسة 14

3) بناء Architecture

ارسم الصفحات قبل الكود:

  • / ترحيب وروابط سريعة
  • /courses قائمة + بحث
  • /courses/:courseId تفاصيل + سعر €
  • /contact نموذج اهتمام متحكم به
  • * صفحة غير موجودة
src/
  components/CourseCard.jsx, SearchBar.jsx, SiteLayout.jsx
  pages/HomePage.jsx, CoursesPage.jsx, CourseDetailsPage.jsx, ContactPage.jsx
  context/AcademyContext.jsx
  hooks/useCourses.js, useCourse.js
  services/courses.js

4) تقسيم التنفيذ (ترتيب العمل في الجلسة)

  1. Vite + Router + Layout + Outlet
  2. AcademyProvider (اسم المدرب + رمز العملة €)
  3. services + useCourses (Loading / Error)
  4. CoursesPage: بحث محلي على العنوان + CourseCard
  5. CourseDetailsPage: useParams + fetch بالمعرّف
  6. ContactPage: controlled form + تحقق + preventDefault
لا تبدأ بالتصميم الثقيل. اجعل التدفق يعمل أولاً: قائمة → تفاصيل → نموذج. ثم حسّن البطاقات.

5) مصدر البيانات

استخدم JSONPlaceholder أو مصفوفة محلية إن انقطع النت في القاعة. بعد الجلب أضف حقول العرض: trainer و price (مثلاً 39 أو 49 €).

مثال 2: بطاقة كورس

function CourseCard({ course, trainer, currency }) {
  return (
    <article>
      <h2>{course.title}</h2>
      <p>{trainer}</p>
      <p>{course.price} {currency}</p>
      <Link to={"/courses/" + course.id}>Details</Link>
    </article>
  );
}

مثال 3: بحث مرفوع للحالة في الصفحة

const [query, setQuery] = useState("");
const visible = courses.filter((item) =>

);

مثال 4: تفاصيل ديناميكية

const { courseId } = useParams();
const { course, loading, error } = useCourse(courseId);

if (loading) return <p>Loading...</p>;
if (error) return <p>{error}</p>;

مثال 5: نموذج اهتمام

function handleSubmit(event) {
  event.preventDefault();
  if (!name.trim() || !email.includes("@")) {
    setError("Enter a valid name and email");
    return;
  }
  setError("");
  navigate("/courses");
}

تمارين عملية — مسار الجلسة

1 الهيكل والمسارات

Layout + أربع صفحات + 404. الهيدر يعرض Osama Bittar من Context.

<Route path="/" element={<SiteLayout />}>
  <Route index element={<HomePage />} />
  <Route path="courses" element={<CoursesPage />} />
  <Route path="courses/:courseId" element={<CourseDetailsPage />} />
  <Route path="contact" element={<ContactPage />} />
  <Route path="*" element={<NotFoundPage />} />
</Route>

2 القائمة والحالات

جلب القائمة مع Loading و Error وفلتر بحث وبطاقة سعر باليورو.

if (loading) return <p>Loading courses...</p>;
if (error) return <p>{error}</p>;
if (visible.length === 0) return <p>No courses match your search.</p>;

3 التفاصيل والنموذج

تفاصيل حسب id، وContact مع تحقق ثم navigate إلى /courses.

navigate("/courses");

اربط التفاصيل بـ getCourseById(courseId) داخل useEffect مع [courseId].

ملخص الجلسة

  • حلّل الصفحات ثم ابنِ المجلدات ثم نفّذ التدفق
  • القائمة والبحث والتفاصيل والنموذج هي العمود الفقري
  • Context للمدرب والعملة لا لكل حقل بحث
  • Loading و Error جزء من المنتج لا زينة لاحقة

واجب الجلسة

  • أكمل كتالوج الأكاديمية حتى يعمل التدفق كاملاً محلياً
  • كل بطاقة: عنوان، Osama Bittar، سعر €، رابط تفاصيل
  • جهّز المشروع للمراجعة في الجلسة 16 (لا تبدأ سلة Reducer هنا إلا إن أنهيت الكتالوج)
